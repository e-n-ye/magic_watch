## 这个项目在简历里最值得讲的主线

如果把 Magic Watch 写成“做了很多智能手表页面”，叙事会偏弱。

当前更有价值的讲法是：

- 这是一个以 LVGL 模拟器为载体、围绕嵌入式 UI 架构收口与可维护性重构推进的项目。

核心不是页面数量，而是：

1. 把巨型 UI 文件逐步按领域下沉。
2. 用 `DataCenter + EventBus + AppStateMachine + PageManager` 组织 UI 与状态。
3. 在不推倒重写的前提下，把模拟器代码往可维护、可扩展、未来可接硬件的方向收口。
4. 用 Scope Lock、手动回归和文档入口治理控制重构风险。

## 当前最适合写进简历的项目定位

### 定位版本 A：偏嵌入式 UI 架构

基于 LVGL PC 模拟器重构智能手表 UI 架构，围绕事件驱动、页面分域、状态协调和低功耗交互路径，逐步将早期巨型页面实现收口为可维护的模块化结构。

### 定位版本 B：偏工程化重构

在不推倒重写的前提下，持续重构智能手表模拟器项目，建立 `DataCenter / EventBus / AppStateMachine / PageManager` 分层边界，分阶段拆解巨型 UI 文件，并通过文档治理与手动回归降低结构迁移风险。

### 定位版本 C：偏“为硬件接入做准备”

以 LVGL 模拟器为预研主线，先完成智能手表 UI 与状态系统的解释力恢复、页面域拆分和生命周期边界梳理，为后续真实硬件接入保留稳定上层架构。

## 当前已具备支撑力的技术亮点

### 亮点 1：巨型 UI 文件按领域下沉

当前可讲事实：

- `Settings / Display` 已拆到二级目录。
- `Power` 域页面已下沉到 `Shell/Power/ShellPowerPages.cpp`。
- `Daily` 域已拆出 `WeatherPages.cpp`、`StepsPages.cpp`。
- `Health` 域已拆出 `SleepPages.cpp`、`BloodOxygenPages.cpp`、`HeartRatePages.cpp`。
- Shell 与 Health 共享 helper 已形成稳定文件组。

简历价值：

- 说明你不是只“写页面”，而是在做结构化重构。
- 能体现模块边界、文件治理、重构节奏控制。

### 亮点 2：事件驱动 UI 架构主线

当前可讲事实：

- 项目主线围绕 `HAL / SimulatorDevice -> Application -> DataCenter / EventBus -> AppStateMachine -> PageManager -> Pages` 展开。
- 页面不直接碰硬件。
- `PageManager` 负责显示与页面栈，不承担业务判断。
- `AppStateMachine` 正朝 Coordinator 方向收口。

简历价值：

- 能体现你理解嵌入式 UI 不只是“画页面”，而是输入、状态、页面、服务之间的分层协作。

### 亮点 3：低功耗与系统态交互路径

当前可讲事实：

- 已形成 `ScreenOff`、`LongBatteryWatchface`、`LongBatteryExit`、`PowerMenu` 等系统态页面路径。
- 抬腕亮屏、遮盖息屏、通知唤醒、息屏显示、持续亮屏等策略存在交界约束。
- 长续航模式与页面栈恢复、通知抑制、主页交互抑制之间存在系统级协同。

简历价值：

- 这比普通 CRUD UI 更接近嵌入式交互系统。
- 能突出你对低功耗模式、状态切换、恢复路径的关注。

### 亮点 4：共享模型与跨页状态同步

当前可讲事实：

- `StepsModel`、Display policy、通知模型、健康监测设置模型都通过共享路径同步多个页面。
- `BatteryOptimizationPage` 与 `Sleep / BloodOxygen / HeartRate` 设置存在共享状态联动。
- 通知列表、notification wake preview、toast 共享同一通知模型路径。

简历价值：

- 说明你处理过跨页状态一致性，而不是单页静态 mock。

### 亮点 5：在重构中建立验证闭环

当前可讲事实：

- 项目保留完整手动回归矩阵。
- 进一步提炼出“按结构风险映射的小包回归清单”。
- 每轮强调 Scope Lock、限制修改范围、收口后检查工作区。

简历价值：

- 体现工程纪律。
- 体现“会做重构，也会控制重构风险”。

## 面试展开时可讲的技术细节

如果面试官追问，可以沿以下路线展开：

### 展开 1：为什么不是直接重写

- 解释项目早期已经累积了大量页面资产。
- 直接重写会失去已有交互样本与验证路径。
- 所以采用“先解释、再分域、再收口边界”的小步重构策略。

### 展开 2：为什么保留聚合头

- 解释实现文件已经迁域，但 `Application.cpp` 注册入口暂时保持稳定。
- 这样可以先降低实现耦合，再处理声明边界治理。

### 展开 3：HeartRate 为什么值得单独讲

- 它不是简单页面跳转问题。
- 当前更难的是测量阶段、timer、wear prompt、结果态切换的生命周期边界。
- 这能体现你对“页面行为状态”和“文件位置拆分”是分开处理的。

### 展开 4：为什么要做回归包映射

- 因为结构迁移后，最容易漏掉的是跨页同步、screen-off 恢复、temporary shell 状态残留。
- 按风险包组织回归，比每次盲跑全量更稳，也比只靠感觉抽查更工程化。
